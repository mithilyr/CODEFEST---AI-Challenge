what is yaml

--- ASSISTANT  2026-09-08T20:50:06.244Z -----------------------------
**YAML** ("YAML Ain't Markup Language") is a human-readable data format used for config files and data serialization — an alternative to JSON or XML that's easier for people to read and write by hand.

Key features:
- **Indentation-based structure** (like Python) instead of braces/brackets
- **Key-value pairs**: `name: value`
- **Lists**: lines starting with `-`
- **Nesting** via indentation
- Supports comments with `#` (JSON doesn't)

Example:
```yaml
member_of:
  inverse: has_member
  fields:
    forward: [Member of, Membership, Affiliation, Allegiance]
    reverse: [Members, Member, Known members]
  cues: [belongs]
```

In this project, it's used for exactly that reason — [config/authority.yaml](e:\AI Challenge CodeFest\ashen-assistant\config\authority.yaml) and [config/relations.yaml](e:\AI Challenge CodeFest\ashen-assistant\config\relations.yaml) hold claims about the corpus (source authority rankings, field-name-to-relation mappings) in a format a judge can open, read in plain English, and argue with — rather than burying that logic in Python literals where it's invisible to a non-coder reviewer.

what is a frozen dataclass

--- ASSISTANT  2026-09-08T21:11:31.793Z -----------------------------
A **frozen dataclass** is a Python `@dataclass` decorated with `frozen=True`, which makes its instances **immutable** — once created, you can't reassign any of its fields.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Settings:
    api_key: str
    corpus_path: str

s = Settings(api_key="x", corpus_path="/data")
s.api_key = "y"   # raises dataclasses.FrozenInstanceError
```

Normal `@dataclass` still generates `__init__`, `__repr__`, `__eq__` for you, but fields stay mutable. Adding `frozen=True` also makes instances **hashable** by default (so they can go in a set or be a dict key) and signals to anyone reading the code that this object represents a fixed, one-time-computed value rather than mutable state.

In this project, [settings.py:31](e:\AI Challenge CodeFest\ashen-assistant\src\settings.py#L31) uses exactly this pattern: `Settings` is a frozen dataclass holding the three API keys plus the corpus path. That's deliberate — configuration loaded once at startup shouldn't be silently mutated somewhere deep in the call stack; if code needs different settings, it should construct a new `Settings`, not reach in and change one field of the shared instance.

What is an API key

--- ASSISTANT  2026-09-08T21:15:13.636Z -----------------------------
An **API key** is a secret string (a long random-looking token) that a client passes along with a request to identify itself to a service and prove it's authorized to use it. Think of it like a password, but for a program talking to another program instead of a person logging into a website.

How it's typically used:
- You sign up with a provider (Google, OpenRouter, Voyage, etc.), and they issue you a key.
- Every request your code sends includes that key, usually in a header (e.g. `Authorization: Bearer <key>`) or as a parameter.
- The provider checks the key to know **who's calling** (for billing/quota tracking) and **whether they're allowed** to call that endpoint at all.
- If the key is missing or invalid, the request is rejected.

Why it must stay secret: anyone with your key can make requests **as you** — burning your quota, seeing your usage, or in a paid service, running up charges on your account.

In this project specifically, [CLAUDE.md](e:\AI Challenge CodeFest\ashen-assistant\CLAUDE.md) and [INTERNALS.md](e:\AI Challenge CodeFest\ashen-assistant\docs\INTERNALS.md#L313-L328) describe three:

| `OPENROUTER_API_KEY` | Tier-3 query planner + optional answer phrasing |
